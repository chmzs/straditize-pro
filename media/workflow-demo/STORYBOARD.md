# 导演构思 / 分镜表 —— Straditize 8 步工作流

## 一句话立意

不是"功能列表轮播"，是**一次真实的测量过程**：把一张扫描图，一步步量成一个带坐标的数据表。
片子跟的不是按钮，是**坐标系的诞生**。

## 三个贯穿装置

1. **产品自带的步骤条就是章节标记。** 每个镜头都推近顶部那条 `1 载入 → 8 校验` 的真实进度条，
   观众永远知道"现在走到第几步"。不另造 HUD，不假造界面。
2. **数字是主角。** 每步只允许一个数字占据画面右下角（lower-third 的大号读数），
   `2339×1654 → 28 → 0.1875 → 20 → 28 → 11 → 112 → 170.8%`。
   结尾用"账本"页把这些数字一次性摆齐 —— 这是全片的兑现时刻。
3. **两个刹车。** 全片有两次故意慢下来、转琥珀色：
   ⑥ 刻度标定（刻距不均，部分列必须手点轴线，不是全自动）、
   ⑧ 导出被拒（没做 Y 轴标定就不给导出，并说明原因）。
   有刹车的演示才可信；只推进的演示是广告。

## 结构：三幕 + 尾账本

| 幕 | 镜头 | 主题 |
| --- | --- | --- |
| I 立框 | ① 载入 → ② ROI → ③ Y 两点标定 | 把图像变成**坐标系** |
| II 分离 | ④ 干扰线清理 → ⑤ 分列命名 | 把混在一起的**拆成单列** |
| III 兑现 | ⑥ X 刻度 → ⑦ 共识层位 → ⑧ QA 与导出拦截 | 把像素变成**可复核的科学数据** |

## 镜头语言

- 每个镜头的节奏固定为 **establish（宽）→ focus（推近证据）→ hold（字幕停留）**。
  单次运镜 1.5–3 s，硬切一律不用。
- 运镜全部 `Easing.bezier(.33,0,.15,1)`（缓入缓出），带位置钳制，画面不出画布外。
- 段间转场：**遮罩滑动**（竖帘 5 帧，帘边一道青光）。开场/账本/收尾三镜硬切。
  不用碎裂/翻转，也不用交叉淡化——两张界面叠一半会成重影；纯排版镜头扫进来则会出现半屏空暗场。
- 指示位置只用**高亮框 + 描边生长动画**，绝不画假鼠标。
- 配色：深海军蓝底 `#060d18`、青 `#22d3ee`、蓝 `#3b82f6`；两次"刹车"切琥珀 `#fbbf24`／警示红。
  界面截图保持原样（产品是浅色 UI），深色底只做承载与聚光。

## 诚实性约束（写进代码注释）

- 字幕数字全部来自当帧截图上的可见文本，无一处估算。
- `modal_export_uncalibrated.png` 是**另一次会话**的截屏（横幅上是 601 层位 / 174.2%），
  与 ⑧ 的 112 / 170.8% 不同源。因此该镜头只取"就绪清单"与"深度标定"提示，
  横幅与表格数字**不入画、不入字幕**，避免把两套数据混成一套。
- ⑦ 的 112 是"拐点共识层位"= 自动提取数；⑧ 的 85 是其中总和超标数。二者是子集关系，字幕分开表述。

## 两版剪辑

同一套分镜出两条：

- **长片**（69 s）：完整运镜 + 焦点模糊转场 + 账本页。文档站与投稿用。
- **动图**（24.7 s）：每个步骤只留一个**定位镜头**（固定 1.2× 裁切在证据处），
  镜头之间硬切，动效交给「高亮描边生长 / 字幕淡入 / 读数上浮」。
  原因不是审美，是 GIF 的差分压缩扛不住整屏推拉（实测 69 s 版转出来 40 MB）。
  首尾各留 10 帧暗场拍子，loop 从暗到暗，衔接不见缝。

动图省掉开场/账本/收尾三镜——网页首屏不需要片头，只需要把 8 步走一遍。
真值一个字没少：`scenario.ts` 的 `STEPS` 两版共用。
