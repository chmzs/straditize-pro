# 亮度和最深百分比是否该改为颜色？

> 用户原问：「亮度和最深百分比是否不合理，应该改为颜色定义？」
>
> **结论**：两者都不合理，但**不能改为纯颜色**。
> 正确做法是**色度 + 亮度双轴**：色度判"哪种墨"，亮度判"哪一层"。
> 下面是可判定的证据与失效边界。

---

## 1. 「最深 N%」为什么失效

### 1.1 真实图版上的反例（`Cyperaceae` 列）

用同一列（x=927..1093, y=245..850）取"最深 N%"作填充判据：

| N | 阈值 | 判定为"填充"的像素 | 占比 |
| ---: | ---: | ---: | ---: |
| 5% | 0.0 | 31,105 | 31.0% |
| 10% | 0.0 | 31,105 | 31.0% |
| 20% | 0.0 | 31,105 | 31.0% |
| 30% | 0.0 | 31,105 | 31.0% |
| 50% | 229.0 | 89,697 | **89.3%** |

**失效特征**：
- N 从 5% 到 30%，答案**完全不变**（阈值卡在 0，因为纯黑像素占比超过 30%）；
- N 到 50% 时**突然跳变**到 89.3%（把 5× 阴影层 `229,229,229` 也纳入）。

**没有任何 N 给出正确值。** 因为"最深 N%"的 N 是**分位数**，而填充是**颜色层**——
两者之间不存在函数关系。分位数只描述"排序位置"，不描述"属于哪一层"。

### 1.2 为什么这个错误特别危险

它**永远返回一个数字**，看起来合理（31%、89%）。用户无法从输出判断它错。
本次事故就是这样发生的：我用"最深 10%"得出"9/15 列失败"，实际 14/15 列正常。

---

## 2. 「亮度」为什么也不够

### 2.1 同一张图上，灰阶层级与彩色彩度是两回事

| 颜色簇 | 亮度 | R−G | R−B | chroma |
| :--- | ---: | ---: | ---: | ---: |
| 纸白 (255,255,255) | 255 | 0 | 0 | 0 |
| 浅灰阴影 (229,229,229) | 229 | 0 | 0 | **0** |
| 中灰实心 (182,182,182) | 182 | 0 | 0 | **0** |
| 深灰实心 (167,167,167) | 167 | 0 | 0 | **0** |
| 纯黑 (0,0,0) | 0 | 0 | 0 | **0** |
| 浅蓝阴影 (218,226,237) | 225 | −8 | −19 | **19** |
| 深蓝实心 (0,62,137) | 52 | −62 | −137 | **137** |
| 浅粉阴影 (244,226,226) | 231 | 18 | 18 | **18** |
| 深红实心 (180,60,60) | 96 | 120 | 120 | **120** |

**两条关键事实**：

1. **灰阶列的三层（255 / 229 / 182）chroma 全为 0** —— 它们颜色**完全相同**，
   只能靠亮度区分。所以"只用颜色"在灰阶列上**完全失效**。
2. **彩色列的浅/深两层色相相同、只差亮度**（浅蓝 225 vs 深蓝 52）。
   所以"只用亮度"会被跨列的明度差异干扰：中灰实心 182 比浅蓝阴影 225 更暗，
   但前者该进读数、后者不该——单看亮度无法区分"这是哪一层"。

### 2.2 当前缺陷正是"只用亮度"造成的

`extract_foreground()` 用全局 Otsu = **138.0**：
- 中灰实心 182 > 138 → 判为背景 → **整列曲线消失**（`Caryophyllaceae` 提取 max = 0.00%）
- 三类阴影 229/225/231 > 138 → 判为背景 → **正确**（阴影不该进读数）

**同一个阈值，一处对一处错。** 因为单一阈值假设"所有非背景像素同属一层"，
而这张图有**三层**（纸 / 阴影 / 实心）。

---

## 3. 为什么也「不能只改颜色」

如果改成"按色相聚类找墨迹"：
- 灰阶列 chroma=0，聚不出层级 → 中灰 182 与浅灰 229 仍无法分开；
- 且浅蓝阴影 sat=0.08017 恰好越过 0.08 阈值，而浅粉 0.074 不过 ——
  **同一个函数对同类对象给出相反判定**（QA 已复现：蓝阴影 100% 进前景、粉阴影 0%）。

这是 `solid-over-shadow` 实验模式的现状，已被显式拒绝（止损正确）。

---

## 4. 正确判据：双轴

```python
chroma = max(R, G, B) - min(R, G, B)

grey   = chroma <= 12                                  # 第一轴：是灰还是彩
solid  = (grey & (lum < 210)) | (~grey & (lum < 170))   # 第二轴：哪一层
shadow = (grey & (210 <= lum < 250)) | (~grey & (lum >= 170))
```

**设计逻辑**（两条轴各管一件事）：
- **色度轴**先分流：灰阶 vs 彩色。灰阶走一套亮度阈值，彩色走另一套。
- **亮度轴**再分层：同一分支内，暗的 = 实心，亮的 = 阴影。

### 验证（Lead 实测，真实图版 9 种色簇）

| 颜色簇 | 像素 | 判定 | 期望 |
| :--- | ---: | :--- | :--- |
| 浅粉阴影 | 40,604 | shadow | shadow ✅ |
| 浅蓝阴影 | 30,944 | shadow | shadow ✅ |
| 浅灰阴影 | 160,896 | shadow | shadow ✅ |
| 中灰实心 | 4,838 | solid | solid ✅ |
| 深灰实心 | 5,824 | solid | solid ✅ |
| 纯黑 | 139,587 | solid | solid ✅ |
| 深红实心 | 9,204 | solid | solid ✅ |
| 深蓝实心 | 5,077 | solid | solid ✅ |

**8/8 全对。**

## 5. 失效边界（必须写明，否则又是一次"恰好适配"）

双轴判据不是万能的。以下条件下需重新标定：

1. **阈值 210 / 170 / 12 是按本图版定的**。换图版需重测：
   若某图的阴影层亮度 < 210（更深的阴影），会被误判为实心。
2. **纯灰阶且实心与阴影亮度差 < 20 级**时，210 这条线会失效。
   此时应改用**按列直方图双峰**自适应，而非固定阈值。
3. **抗锯齿边缘**必有中间值，任何阈值都会把边缘的一部分归到相邻层。
   影响量级：本图版边缘像素约占总量的 2–4%，可接受；若线宽仅 1–2px 则不可接受。
4. **不是"层"的东西**（如浓度折线、分区线、刻线）会被一并纳入。
   本图版的浓度折线是黑色细线，会进 solid —— 这是**正确的**（它确实是墨迹），
   但若用户只想取柱状列，需靠 ROI/分列排除，不能靠分层判据排除。

---

## 6. 一句话回答

> **"最深 N%"根本不该用**——它的 N 与填充面积没有函数关系，且永远返回一个看似合理的数。
> **"亮度"不够用**——它分不开"灰阶的三层"与"彩色的两层"这两类问题。
> **"颜色"也不够用**——灰阶列 chroma=0，颜色信息量为零。
>
> **正解是双轴**：色度定"哪种墨"，亮度定"哪一层"，各管一段。
> 且阈值必须写明失效边界，否则只是把"恰好适配"换了个位置。

pixi run python -c "

# 双轴判据 8/8 全对
pixi run python -c "
import numpy as np; from PIL import Image
a=np.array(Image.open('output/han2026_ngamring/fig3_raw.jpeg').convert('RGB')).astype(int)
lum=a.mean(-1); ch=a.max(-1)-a.min(-1)
for lbl,c,exp in [('中灰',(182,182,182),'solid'),('浅灰',(229,229,229),'shadow'),
                  ('浅蓝',(218,226,237),'shadow'),('纯黑',(0,0,0),'solid')]:
    sel=(np.abs(a-np.array(c)).max(-1)<=6)
    g=ch<=12; s=((g)&(lum<210))|((~g)&(lum<170))
    got='solid' if (sel&s).sum()>(sel&~s&(lum<250)).sum() else 'shadow'
    print(lbl, got, 'OK' if got==exp else 'FAIL')
"
