## §3 需求未定义（需产品决策，不做缺陷裁定）

1. **撤销是否应覆盖清理编辑（笔迹/几何/排除区）**
   现状：`docs/testing-strategy.md:319` 已把"清理编辑不入栈"定为产品决策，回收出口是显式的「清空笔迹」。
   待决：T-03 的体验问题正是这个决策的副作用——按钮可按、按了却作用到别的对象。需要决定：(a) 维持现决策 + 按钮在此时禁用/给出"本步编辑不可撤销"提示；(b) 扩栈支持逐笔撤销（后端 `setLineStrokes` 是全量覆盖，技术上可行）。
2. **「+ 新建 ROI」的初始边界**
   现状：克隆当前 ROI 边界（`InspectorBridge.ts:149-152`），3/3 得到 100% 重叠；UI 无任何区分或提示。
   待决：新建应是"待框选的空区域"、"在既有区内缩进的副本"，还是"故意允许共面（不同指标从同一区域取数）"？只有定了这条，F-07 的"几何"部分才能裁定。
3. **「保存项目」应导出什么**
   现状：按钮叫"保存项目"，实际调 `export.tar`（数据交付包）；后端另有 `project.save`（工程包，可载回继续编辑）。
   待决：是两个按钮（"保存项目"vs"导出数据")、还是一个按钮一个包？这直接决定 T-05 的修法方向。
4. **Y 标定框空值时的占位符语义**
   现状：占位符是硬编码 556/0/1320/1500，与图像无关（两图同值，且 1320 超出 745 高的图）。
   待决：占位符应显示什么——留空、显示"请输入"、还是显示按当前 ROI 计算出的建议行号（若显示建议值，就必须可区分"建议"与"已填"）。
5. **撤销按钮的可用性语义**
   现状：栈里有"与本步无关"的历史项时按钮可按，按下可能空转（同值 `roi.update`）或改动画布上用户没预期的对象。
   待决：空转项是否应不入栈/入栈时校验有效性。

## §4 裁定方法与次数

统一方法：真实 UI 点击/拖拽（`cursor: ns-resize` 命中 ROI 手柄、canvas 真实鼠标轨迹涂抹）；每次动作后读 `straditize.getDiagramData`（只读）作为权威状态；RPC 计数来自页面内 `fetch` 透传包装器（记录 `method/id/params`，不拦截、不改写）。截图由裁定人本轮重新拍摄。

| 条 | 尝试次数 | 命中 | 差异说明 |
|---|---|---|---|
| T-01 页脚缩放 | 3 | 3 | 尝试 1 纯点击（1:1/适应/滚轮）；尝试 2 先切步骤再点；尝试 3 **换图**（01_chinese）。三张图/三条路径同结论：页脚停在载图时的值 |
| T-02 空标定静默 | 3 | 3 | 前 2 次在 01_chinese、第 3 次在 hoya；都是 0 RPC/0 提示。另做对照（填值后同一按钮 → 2 条 `calibrateAxes`、HUD 更新），证明不是按钮失效 |
| T-03 清空笔迹后撤销 | 4 | 4（"笔迹不恢复"）／0（"回退 ROI 几何"） | 尝试 1–2 用改名/几何历史；尝试 3 栈近空；尝试 4 专为 Explorer 路径先拖 ROI 到 287 再复测。差异只在"撤销发出的请求形态"：同值 `roi.update` / 无请求 |
| T-04 面板否定标定 | 3 | 2 | 尝试 1 照抄 Explorer 路径（步骤 4 撤销→上一步）**未命中**；尝试 2/3 按机制构造（栈内保留标定前快照）**命中**。Explorer 记 1/3 与我的 2/3 同源，差异来自栈内容而非动作序列 |
| T-05 保存/打开往返 | 3 | 3 + 1 次对照 | 3 次都是同一个 tar（SHA256 校验同文件）；第 4 次用 `project.save` 工程包做对照，成功载入 → 证明打开端本身可用 |
| T-06 重复写请求 | `roi.update` 3 / `calibrateAxes` 4 | 3 / 4 | `roi.update` 每次都 2 条（4 条请求 = 2 对）；`calibrateAxes` 条数为 2/3/2/2，比 Explorer 记录的"间歇 1~2 条"更严重 |
| T-07 名源错误 | 3 | 3 | 连续新建 3 个 ROI，边界与名源全同 |

方法学自纠一处：T-02 我先接受了 Explorer"占位符＝后端已有值"的说法，随后用**第二张尺寸完全不同的图**做对照才发现占位符是常量（`1320` 超出 745 图高）。该纠错已写进 T-02 的"代理指标纠错"行，避免把巧合当机制。

取证披露（不隐瞒代理手段）：T-05 的对照实验中有一步用一次直接 RPC（`roi.update` 改名到 `湖泊C`）制造状态，之后改用真实 UI 改名（`湖泊E`）复做，结论一致；缺陷表里所有"实际"读数分别来自 UI 动作 + 只读探针，无不一致。
