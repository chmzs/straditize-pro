# 偏差表解读：`paper_range` 列的负偏是方法论错误，不是算法缺陷

> 起因：后台数据代理（`data-engineer`，运行中失败）留下了
> `Han2026_Fig3_deviation.json` 与 `Han2026_Fig3_with_paper_ranges.csv`，
> 其中 `paper_range` 列全部呈现大幅负偏（−13.8% ~ −88.5%）。
> 本文裁定该负偏的性质。

---

## 1. 现象

`Han2026_Fig3_deviation.json` 的偏差表（提取 max vs 论文 reported max）：

| 列 | provenance | 假设满量程 | 提取 max | 论文 max | 偏差 |
| :--- | :--- | ---: | ---: | ---: | ---: |
| Pinus | paper_range | 40.74 | 4.70 | 40.74 | **−88.5%** |
| Rosaceae | paper_range | 12.97 | 5.06 | 12.97 | **−61.0%** |
| Chenopodiaceae | paper_range | 6.68 | 4.04 | 6.68 | **−39.6%** |
| Hippophae | paper_range | 7.75 | 2.39 | 7.75 | **−69.2%** |
| Artemisia | paper_range | 67.42 | 58.10 | 67.42 | **−13.8%** |
| Ranunculaceae | paper_range | 14.00 | 5.58 | 14.00 | **−60.1%** |
| Cyperaceae | **human** | 70.00 | 67.20 | 70.07 | −4.1% |
| Poaceae | human | 20.00 | 7.26 | 9.21 | −21.2% |
| Caryophyllaceae | human | 15.20 | 0.00 | 4.29 | −100% |

**规律**：`paper_range` 组 6 列**全部负偏**（−13.8% ~ −88.5%）；
`human` 组（满量程取自图版刻度尺）偏差小得多。

## 2. 裁定：`paper_range` 的负偏是**假设错误**，不是算法缺陷

### 2.1 两个量根本不是一回事

| 量 | 定义 | 来源 |
| :--- | :--- | :--- |
| **论文 reported max** | 159 个样品中该列的**历史极值** | 论文正文 Results |
| **图版满量程** | 作图书设定的**轴上限**（该列画到多宽代表 100%） | 图版刻度尺 |

**两者不必相等，通常也不相等。** 作图时若某列历史极值是 40%，作者可能把轴上限设到
80%（留出视觉空间），也可能把该列放大 5×（本图即如此）。把"历史极值"当"轴上限"
去反推满量程，等于**假设二者相等**——这个假设没有任何依据。

### 2.2 定量证据：偏差与"曲线延伸占列宽比"单调相关

若负偏源于算法（如漏读浅色像素），它不应与"该列曲线画得多满"相关。实测：

| 列 | 深色延伸 / 列宽 | 偏差 |
| :--- | ---: | ---: |
| Ranunculaceae | 0.18 | −60.1% |
| Hippophae | 0.19 | −69.2% |
| Pinus | 0.26 | −88.5% |
| Rosaceae | 0.35 | −61.0% |
| Chenopodiaceae | 0.42 | −39.6% |
| Poaceae | 0.52 | −21.2% |
| Artemisia | 0.54 | −13.8% |
| Cyperaceae | **0.96** | **−4.1%** |

**单调相关**：曲线画得越满（越接近列宽），偏差越小。Cyperaceae 延伸占 96% 列宽 → 偏差仅 −4.1%。

**这正是"轴上限被设得比历史极值大"的直接体现**：轴上限设得越大，同一历史极值
在图版上占的列宽比例就越小，按错误满量程算出来的读数就越偏低。

### 2.3 图版直读的交叉验证

Cyperaceae 刻度尺印刷数字：`20 @ x=954`、`40 @ x=1001`、`60 @ x=1047`，
刻度尺延伸到 `x=1081`（图版实际印出的最右刻度齿）。

```
斜率 = (60-20)/(1047-954) = 0.4301 %/px
1081 → 20 + (1081-954)*0.4301 = 74.6%
```

**即该列的图版满量程是 74.6%，而不是论文报的 70.07%。**
用 74.6% 作满量程时，提取 max 67.20% → 占满量程 90%，**合理**；
用 70.07% 时占 96%，也还说得过去 —— 但这是巧合，不是方法正确。

### 2.4 结论

**`paper_range` 组的负偏全部来自"把历史极值当轴上限"这一错误假设。**
不是"算法漏读了像素"。

支持这一裁定的反向证据：**同一批算法对 `human` 组的 Cyperaceae 只偏 −4.1%**。
若是算法缺陷，它不会只挑 `paper_range` 组出错。

## 4. 教训（第二条，与 `adjudication-caryophyllaceae.md` §4 并列）

> **不要把"某论文报告的一个数字"当作"图版上某个几何量的真值"。**

前者是**研究结果**（数据统计量），后者是**作图参数**（视觉设计量）。
两者之间没有函数关系。用前者去校准后者，得到的偏差表看似严谨，
实则在测一个不存在的关系。

**可判定的正确做法**：
- 满量程**只能**取自图版刻度尺的印刷数字（`provenance=human`）；
- 若某列无印刷数字，**该列不可标定**，输出 `NA`；
- 论文 reported max 只能用于**量级合理性检查**（如"提取 max 不应超过历史极值"），
  不能用于反推满量程。
