# 步骤 7 探索实验报告：亚像素边缘（B1）与最优 L∞ 分段（B2）

日期：2026-11-16 ｜ 分支：explore/step7-subpixel（从 A 线提交起，独立 commit，可整段回滚）
脚本：support/explore_step7_bench.py（跑法：python support/explore_step7_bench.py）

## 0. 结论先行

* **B1（亚像素边缘）在本仓库语料上没有优势**：抖动 std 中位数变差 1.48 倍（135 个
  可比配置里 109 个变差、23 个变好），单列实测亚像素边缘相对二值边缘平均位移
  0.99~1.58px（不是 0.1~0.2px），最坏一例位移 199.96px（窗口把邻列墨迹卷进来）。
  不建议合入。
* **B2（Imai-Iri 区间 DP）在理论上确实最优**：同 eps=2.0 下 107/153 个配置比 RDP 少点、
  44 个持平、2 个更多，平均少 3.69 个点（中位 20 → 18），误差界严格成立（max<=2.00）。
  代价是耗时 100 倍以上（中位 126ms vs RDP <1ms，最坏 828ms），不建议进生产路径，
  建议保留为"最优性标尺"，用于评估任何启发式简化器离最优有多远。
* 现状实现（A 线：垂直 RDP + 极值锚点 + 去堆积 + 误差界兜底）在本矩阵 153 个配置上
  **P95 中位 0.93px、p90 1.50px、最差 1.80px**，全部 <= 2px。

## 4. B1 亚像素：详细判定（结论：没优势）

### 4.1 抖动没降
135 个可比配置里，亚像素轮廓的 mean|dw| 相对二值轮廓的比值：中位 **1.478**，
p10 0.908；只有 23 个配置变好，109 个变差。逐图看（第 2 节表）最差的是
scan01_hlines（2.89 -> 7.94）、scan02_multicolor（4.96 -> 10.69）、
type6_composite_zonation（0.98 -> 5.22）。

### 4.2 边缘位移不是 0.1~0.2px，是 1~2px
三列实测（binary = 最右墨迹像素 + 1，subpixel = ±2px 窗口内 |gx| 加权一阶矩）：

| 图/列 | span | 可用行 | binary mean\|dw\| | subpixel mean\|dw\| | 比值 | \|sub-binary\| 均值 / p95 / max | \|diff\|>1px 行数 |
|---|---|---|---|---|---|---|---|
| type4_pure_line col0 | 114 | 143/199 | 1.521 | 1.475 | 0.97 | 1.535 / 2.415 / 6.680 | 100/143 |
| fig3_raw col9 | 212 | 633/637 | 3.778 | 4.756 | 1.26 | 0.991 / 0.938 / **199.960** | 29/633 |
| scan01_hlines col1 | 83 | 354/588 | 1.320 | 1.580 | 1.20 | 1.575 / 1.787 / 76.000 | 255/354 |

### 4.3 为什么没有优势（三条机制）
1. **读的不是同一条边**。area 读"最右墨迹"，line 读"填充顶边/曲线中心"，bar 读"柱右缘"。
   三者在同一张图上不是同一条边；|gx| 一阶矩只对"墨->纸"的单向导数有定义，
   对只有 1~3px 宽的细线，窗口内的导数峰有两个（线两侧），矩心落在两峰之间 =
   系统偏移（type4 实测 1.5px）。
2. **窗口污染**。±2px 窗口在窄列（span 13~39px）里占掉可观比例；相邻列的轴线、
   横线、分区带都会被算进权重。fig3 col9 的 199.96px 位移就是邻列墨迹进了窗口。
3. **量化噪声不是抗锯齿噪声**。逐行宽度的抖动主要来自 1px 阶梯（墨迹右缘整像素跳变），
   不是灰度过渡的亚像素抖动；梯度矩在阶梯上不提供额外信息，只把噪声重新分配。

### 4.4 失败案例清单（图 / 列 / 现象）
* type5_presence_symbols：选中的列 600 行全部"无墨迹"（flag 1），亚像素无定义；
  该图 area 读数恒 0，本身就是"符号点位"而非连续曲线，任何逐行宽度方法都不适用。
* diatom_rioja col12（span 27）：487 行无墨迹，亚像素退化为二值。
* scan02_multicolor col7（span 62）：18 行"墨迹分段间隔 > 4px"（flag 2），
  多色/双轴图里彩色线条被灰度阈值切成多段。
* scan01_hlines / fig3_raw：横线行（hline_rows）未参与亚像素（flag 已标），
  但窗口内的横线仍影响相邻行 —— fig3 col9 的 199.96px 即此类。
* pollen_curvestyle col20（span 125）：现状 P95 1.64 → 纯 vrdp 2.00，
  说明"只上垂直 RDP、不做锚点/去堆积"会比 A 线现状略差（A 线靠去堆积后的
  误差兜底把误差压回来）。这条是**对 A 线的补充证据**，不是 B1。

## 5. B2 Imai-Iri DP：详细判定（结论：最优但太慢）

| 指标 | RDP（垂直，eps=2） | Imai-Iri DP（eps=2） |
|---|---|---|
| 点数中位 | 20 | 18 |
| 点数最少/最多 | — | 107 个配置更少、44 持平、2 更多 |
| 平均省点 | — | 3.69 |
| 误差界 | max <= 2.00 | max <= 2.00 |
| 耗时中位 / 最坏 | <1ms / 8ms | 126ms / 828ms |
| n=1249 情形 | ~5ms | 0.5~0.8s |

结论：DP 的价值在于给出"同 eps 下最少顶点"的标尺。RDP 平均只多 3.69 个点
（约 10~18%），在用户"点数不敏感、只要准"的口径下不值得换 100 倍耗时。
若将来要压点数（例如导出 SVG 体积），应换 DP 而不是放宽 eps —— 放宽 eps 会直接
破 P95 判据，DP 不会。
2 个 dpLose 的配置（DP 比 RDP 点数更多）说明 RDP 的竖直判据在个别列上"碰巧"
更省，属于 RDP 的分割点恰好落在阶梯上的偶然，不是 DP 有错。

## 6. B3 纸面评估（不写代码）

* **ℓ1 趋势滤波（Kim, Koh, Boyd, Gorinevsky 2009, SIAM J. Imaging Sci.）**：
  解 min 0.5||y-x||^2 + lambda||D^2 x||_1，得到二阶差分稀疏的分段线性趋势，
  结点数由 lambda 控制，凸问题（ADMM 可解）。
  解决的问题：噪声下的分段线性**趋势**估计 + 自动选结。
  与 B2 的关系：目标函数不同——ℓ1-TF 优化的是 L2 残差 + 稀疏性，B2 优化的是
  L∞ 残差 + 顶点数。我们的判据是 P95/max 重构误差，属 L∞ 口径，ℓ1-TF 不保证
  任何 L∞ 界，因此**不能替代** B2/垂直 RDP 的判据作用；它更适合"先把阶梯噪声
  降成平滑趋势再加点"，属预处理。
  与 B1 的关系：不重复。B1 改的是像素定位精度，ℓ1-TF 改的是曲线的正则化，
  两者可叠加，但本报告已证明 B1 在本科语料上无收益，叠加也就无从谈起。
  风险：lambda 一旦放大，台阶会被抹平（与 col01 的 110px 同类风险），
  必须用 L∞ 复核，等于又回到 B2 的判据。

* **单调分段 + PAVA（ isotonic regression，Barlow/Bartholomew）**：
  解决的是"块内必须单调"的约束回归（累计百分比、深度单调的丰度）。
  它不是分段线性近似器：对振荡剖面（本语料绝大多数）会把真实回折压平，
  等于主动删掉用户要的凸点。**与 B1/B2 不重复，但对本任务不合适**——
  除非把"单调块"作为额外的用户先验输入（例如分区带内单调），那属于交互层的
  功能，不是拐点算法。

## 7. 取舍建议

1. B1 不合入；如要再试，必须先按 reader 语义分别定位特征（area = 最右墨迹边界、
   line = 填充顶边、bar = 柱右缘），并把横线/邻列排除在窗口外，然后重新量抖动。
   本轮的失败是可解释的（读错边 + 窗口污染），不是实现细节没调好。
2. B2 不合入生产路径，保留脚本作为标尺；若要压点数可另开分支接 DP + 空间索引。
3. B3 两条都不进代码；ℓ1-TF 若要用，必须外挂 L∞ 复核，收益不明确。
