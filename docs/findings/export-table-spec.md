# 研讨：导出的表应该是什么，以及怎么构建

> 2026-11-19。起因：同一工程能导出 5 种不同的表（89.66% 单元格不同）。
> 结论：**表是「图的数值转录」，不是「实验室原始数据」。这两件事必须分开命名。**

## 一、定义：表是什么

### 1.1 一句话

> 导出表 = **图上每个可读位置的真实墨迹值** + **每行的身份标注** + **每列的换算依据**。

它转录的是**作者的图**，不是实验室的计数。图是作者对数据的可视化，中间已经过取舍（等值线粗细、缩放、夸张、四舍五入）。

### 1.2 四个要素

| 要素 | 定义 | 必需 |
|---|---|---|
| **行** | 图上的一条 y 位置（像素行），**身份必须标注**（见 1.3） | 是 |
| **列** | 图上被标注的一个分类（taxon）；派生列（A/C、总浓度）标 `derived=true` | 是 |
| **值** | 该行在该列的**真实墨迹右缘**，经该列量程换算后的数 | 是 |
| **元数据** | 每列量程来源 / 倍率 / 图 hash / 行集 provenance / 参数 / 生成时间 | 是 |

### 1.3 行身份：四种，只有一种能叫"样品"

| provenance | 含义 | 能否称"样品" |
|---|---|---|
| `samples` | 用户确认的层位（共识 + 人工增删 / 按 N 对齐） | **能** |
| `control_points` | 控制点并集（6530 点 → 1467 行） | 不能 |
| `depth_grid` | 用户给的等间隔 | 不能 |
| `pixel_rows` | 逐列数字化的像素行并集（= ROI 高度） | 不能 |

**软件不推断"真实样品数"。** 论文的 159 是用户读来的外部事实，它的用途是**对齐**（把 203 个候选调到 159 附近），不是**生成**（不能凭 N 造 159 行）。

### 1.4 值的唯一来源：读，不插值

| 做法 | 语义 | 判定 |
|---|---|---|
| `read_column_values(该行)` | 读该 y 位置的真实墨迹 | **正确** |
| `extract_grid_values(depths)` → `np.interp` | 在深度轴上插值 | **错误** |

理由（实测）：`.recon_20261117`，`samples=203` 时两条路径给 203 行 vs 1467 行，**共同行上 89.66% 的值不同**，p95 差 779；`samples=0` 时 max 差 83895.7（浓度列）。插值端点 clamp 会造出**作者没画过的值**。

## 二、构建链：八步，每步一个入口

| 步 | 动作 | 唯一入口 | 失败条件 |
|---|---|---|---|
| 1 | 读图 | `load_image` | 读不到 → 报错 |
| 2 | 检测列 | `detect_columns`（用户可调边界） | 0 列 → 报错 |
| 3 | 数字化 | 逐列 `digitize`（area/line/bar） | 该列无墨迹 → 标 `empty`，不填 0 |
| 4 | 标定 | 每列量程（两点 / 组斜率）+ **零点唯一定义** | 缺量程 → 该列拒导出 |
| 5 | **行集选择** | `_resolve_rowset`（用户显式选 dataset） | 空 → 报错或明示 |
| 6 | **取值** | `read_column_values`（**不插值**） | 该行无墨迹 → `NA` |
| 7 | 序列化 | `serialize_export_frame`（LF / NA / -0.0 规整） | — |
| 8 | 出口 | 所有出口读**同一份快照** | 出口间不一致 → 视为缺陷 |

**被删除或降级的分叉**：

| 现分叉 | 处置 |
|---|---|
| `extract_grid_values` 作为取值入口 | **降级**为"仅在用户明确要求插值时可用"，默认不走 |
| `union_points` 作为独立 dataset | **降级**为"行集选项"（control_points provenance），不再是另一套取值路径 |
| 逐列 `digitize` 的零点（不认组值） | **归并**到 `resolve_column_scale(...).abs_px0` |
| `column_points` 不落盘 | **修**：落盘或记录快照摘要 |

## 三、对抗性意见（我认为必须说出口的）

### 3.1 精度是伪精度

论文 159 个样品落在 478px 里 = **3.01 px/样品**；即使用户重做的 1520px 图，也才 9.56 px/样品。**1px = 0.238%**。

作者的作图本身已经丢失了比 0.238% 大得多的信息（线宽、抗锯齿、印刷误差）。所以：

> 导出值精确到 0.1% 是**没有依据的**。合理做法是给 2–3 位有效数字，并显式标注 **±1px × value_per_px** 的不确定性。

### 3.2 "唯一正确的表"可能是伪命题

不同用途需要不同的表：

| 用途 | 需要什么 |
|---|---|
| 复现论文的图 | 与作者画的每一个 y 位置对齐（数据行可上千） |
| 进 Neotoma / Pangaea | 真实样品层位（159 行），带年代与不确定性 |
| 做统计（DCA/PCA） | 样品×分类矩阵，不能有 NA |

**所以正确做法不是"统一成一张表"，而是"每张表都明确标注它是哪一种"。** 现有 `RowSet.provenance` 已经在做这件事，缺的是：**出口不再让用户选到语义错配的组合**。

### 3.3 最尖锐的一条

> 如果用户要的是"实验室原始数据"，那这张软件给不了。它给的是"图中的数值转录"。

这个区别必须写在导出物的 `README.txt` 第一行，而不是藏在元数据里。因为两者差的是**一个数量级的可信度**。

## 四、判据（可机检）

1. **出口一致**：同一状态、任意两个出口 → `sha256` 相同
2. **行身份可见**：`provenance` 在 API、面板、manifest、README 四处一致
3. **不插值**：`union_points` 的值与 `read_column_values(同 row)` **逐位相同**
4. **零点单入口**：改 `DEFAULT_AXIS_STROKE_PX` ±1px → `scaleCalib` 与 `controlPoints` **同步变化**
5. **不虚构**：`samples` 为空时，任何出口都不得出现"样品"字样
6. **不确定性**：每列带 `uncertainty = 1px × value_per_px`
7. **行数可解释**：`rows_count` 必须能由 `provenance` + 参数解释（像素行 = ROI 高度；samples = 用户确认数；control_points = 去重 row 数）
8. **反向哨兵**：上述任一维度出现"改一个、另一个不变"，即为本类缺陷复发

## 五、落地顺序（先归一，后固化）

| 步 | 内容 | 为什么这个顺序 |
|---|---|---|
| 1 | 取值归一（`union_points` 改读不插值） | 它改变 89.66% 的数值 |
| 2 | 零点归一（`controlPoints` 走 `resolve_column_scale`） | 它改变全部控制点 |
| 3 | 行集选项化（`union_points` 降级为 provenance，不再是另一条取值路径） | 归并后语义才清晰 |
| 4 | 快照持久化 + `stale` 判定 | **必须最后**：先固化会把错的固定成标准答案 |
| 5 | 不确定性列 + README 首行声明 | 交付物层 |

## 六、一句话结论

> **导出的表是「图的数值转录」，行身份必须自证，值只能读不能算，不确定性必须外露。**
> 声称它是"实验室原始数据"是错的；声称"行数等于样品数"在 `samples` 为空时是错的。
